# 实习打磨路线图

这份路线图的目标不是把项目做成“大而全平台”，而是把它打磨成一个对中小厂实习岗位更友好的 Demo。

## 目标岗位建议

### 主投方向

- `Java 后端`
- `后端开发`

### 可兼投方向

- `AI 应用开发`
- `Agent 应用开发`

## 推荐定位

最稳的定位不是“纯 Agent 工程师”，而是：

**会做 AI 应用落地的 Java 后端开发**

这样做的好处：

- Java 岗位池更大，更适合校招和实习阶段起步
- 你的项目里已经有 Agent 亮点，不需要额外硬凹标签
- 面试官更容易理解你的能力边界

## 为什么不建议现在全押纯 Agent

对学生实习来说，纯 Agent 岗位通常有两个特点：

- 数量更少
- 对工程、模型、产品理解要求更高

如果现在把自己完全包装成“Agent 开发”，容易出现两个问题：

- 岗位池变窄
- 面试中被追问到框架原理、多 Agent 编排、评测体系时压力更大

更好的路线是：

1. 先用 Java 后端能力拿到机会
2. 再把 Agent / AI 应用能力做成差异化标签

## 你的项目目前最该补的点

### P0：必须先做

- 修复当前分支的编译问题
- 跑通从登录到出图的完整链路
- 统一接口返回体
- 增加全局异常处理
- 给任务绑定真实用户归属
- 修复知识库存储链路

### P1：面试体验提升很大

- 增加任务列表页
- 增加任务失败原因展示
- 增加任务重试
- 增加参数校验
- 增加 README 与接口文档
- 增加最少量可复现测试

### P2：可选加分项

- docker-compose 一键启动依赖
- 演示视频
- 架构图
- 简历项目描述
- 面试问答准备

## 7 天打磨计划

### Day 1：先把项目修到能跑

- 修复 `ComfyUiService` 与 `GameAssetService` 接口不一致问题
- 确保 `clean compile` 通过
- 本地跑通一次完整链路

交付结果：

- 项目能启动
- 能登录
- 能提交任务
- 能看到至少一条完整生成链路

### Day 2：把后端接口收口

- 为登录、任务查询、任务提交定义统一返回体
- 补全全局异常处理
- 用 DTO 替代 `Map<String, String>`
- 增加基础参数校验

交付结果：

- 面试时能讲“接口规范化”和“错误处理”

### Day 3：把任务系统做得像后端项目

- 增加“我的任务列表”
- 增加任务详情
- 增加失败原因
- 增加重试能力
- 把任务和用户真正绑定

交付结果：

- 项目从 Demo 感变成业务系统感

### Day 4：把知识图谱链路补稳

- 修复 `saveCharacter` 真正入库
- 校正 `saveLore` 参数顺序
- 补角色查询返回结构
- 增加至少一个角色关系示例

交付结果：

- Agent 不再只是聊天壳，而是真能访问知识层

### Day 5：文档和演示材料

- 完善 README
- 增加接口说明
- 增加架构图
- 准备演示脚本

交付结果：

- 别人打开仓库能理解你做了什么

### Day 6：简历和项目讲法

- 写 3 版项目描述
- 准备 1 分钟、3 分钟、5 分钟介绍版本
- 准备“为什么选这个技术栈”的回答

交付结果：

- 项目不只是能做，还能讲得清楚

### Day 7：保留 Agent 亮点，但不过度发散

推荐只保留这几项：

- 自然语言任务下发
- 工具调用
- 知识查询
- 流式响应

不建议继续重投精力做：

- 多 Agent 协作编排
- 自研 Agent 框架
- 复杂评测平台
- 大规模前端可视化重构

交付结果：

- 亮点保留，范围可控

### 偏 AI 应用版本

### 推荐折中版本

`AIGC GameFlow：面向游戏世界观与资产生成的 AI Native 后端系统`

## 项目描述模板

### 模板 1：主投 Java 后端

- 基于 Spring Boot 搭建 AIGC 后端系统，整合 JWT、Redis、RabbitMQ、MySQL、MinIO，实现任务鉴权、异步处理、状态缓存与结果存储
- 设计图像生成异步任务链路，将请求入口与耗时生成流程解耦，支持任务提交、状态轮询与失败处理
- 接入 Neo4j 与 LangChain4j，为游戏角色设定查询和自然语言任务下发提供支持

### 模板 2：主投 AI 应用 / Agent

- 基于 LangChain4j 构建游戏世界观 Agent，支持自然语言交互、知识查询、工具调用与图片生成任务编排
- 接入 DeepSeek 和 ComfyUI，打通从提示词优化到图像生成、资产存储的完整 AI 应用链路
- 结合 Neo4j 图谱与异步任务系统，探索 Agent 在内容生产场景中的落地方式

## 面试里最容易被问到的问题

- 为什么用 RabbitMQ，而不是同步调用？
- Redis 在这个项目里解决了什么问题？
- 任务状态怎么设计？
- JWT 怎么做鉴权？有没有过期控制？
- Neo4j 在这里比 MySQL 多了什么价值？
- Agent 和普通聊天接口的区别是什么？
- 如果 ComfyUI 很慢，你怎么保证系统不阻塞？

## 推荐回答思路

### 关于方向选择

如果面试官问你“你到底想做 Java 还是 Agent”，建议回答：

> 我现在的主能力还是 Java 后端，希望先进入能做真实业务系统的团队；同时我对 Agent / AI 应用落地很有兴趣，所以我会优先寻找两者结合的岗位，比如 AI 应用后端、智能体平台后端、AIGC 业务后端。

这个回答的好处是：

- 不会显得方向漂
- 不会让人觉得你基础不稳
- 还能保住你对 Agent 的兴趣标签

## 一句话结论

如果你的目标是尽快拿到实习：

**先用 Java 后端能力站住，再用 Agent 项目把自己做出区别。**
